# Solopreneurs Radar

Статический сайт для GitHub Pages: главная с плитками, русскоязычные описания и ссылки на внешние первоисточники. Готовые HTML-файлы работают без сборки и установки зависимостей.

В библиотеке один кейс: «Cal AI: подсчёт калорий по фото». Заголовок и полный русскоязычный текст предоставлены пользователем. Источник — публикация TechCrunch от 16 марта 2025 года.

## Публикация в GitHub Pages

1. Создать публичный репозиторий `assistantacc/solopreneurs-radar`.
2. Загрузить содержимое этой папки в корень ветки `main`. Файл `index.html` должен лежать в корне репозитория.
3. В Settings → Pages выбрать Deploy from a branch, ветку main и папку /(root), затем Save.
4. Дождаться завершения публикации. Адрес сайта: https://assistantacc.github.io/solopreneurs-radar/

Для публикации используйте ветку `main` и корневую папку репозитория; отдельный workflow для сборки сайта не требуется.

## Добавление кейса

1. Найти внешний материал с рассказом владельца бизнеса или интервью с ним и прочитать его.
2. Подготовить краткий самостоятельный пересказ на русском языке, сохранив ограничения и период истории. Не приписывать ИИ действия, о которых нет сведений в оригинале.
3. Добавить запись в `content/cases.json`: название, аннотацию, разделы описания, дату первого добавления на сайт `addedAt`, объект `source` с точным URL оригинала, названием, автором, датой публикации и датой проверки, а также метки в `filters`.
4. Выполнить `node scripts/build.cjs` из этой папки. Генератор обновит карточки, страницы и нижний список источников из одного файла.
5. Загрузить обновлённые файлы в репозиторий GitHub Pages.

Плитки на главной ведут на внутренние страницы с русскоязычным описанием. Нижний блок «Все кейсы: первоисточники» ведёт прямо на внешние статьи или интервью, а не на страницы GitHub и не на главную страницу продукта. На каждой странице также есть кнопка «Читать оригинал», URL и сведения об источнике. Внешние ссылки открываются в новой вкладке.

Генератор требует HTTPS-ссылку на внешний первоисточник для каждого кейса и отклоняет github.com и github.io. Файл данных доступен публично вместе с сайтом, поэтому в нём должны быть только материалы, предназначенные для публикации.

Поиск и чтение сайтов выполняет ChatGPT при обновлении библиотеки. Автоматический сбор по расписанию пока не настроен.

## Фильтры

Перед карточками расположены шесть выпадающих списков: «Программные продукты», «Тип клиента и рынка», «Отрасль», «AI-технологии и подходы», «Монетизация» и «Давность». На узком экране строка прокручивается горизонтально. Большой заголовок над библиотекой убран.

Рядом с фильтрами добавлено поле «Поиск: продукт, функция и пр.» и кнопка «Найти». Поиск запускается кнопкой или Enter. Он ищет в заголовке, кратком и полном описании, разделах, назначенных категориях и сведениях об источнике каждого кейса. Регистр не учитывается, «е» и «ё» считаются одинаковыми. Для нескольких слов кейс должен содержать каждое из них. Введённый текст трактуется буквально, без выполнения HTML или регулярных выражений.

Поиск совместим с выбранными фильтрами и «Давностью». Кнопка сброса очищает запрос, категории и возвращает сортировку «Сначала новые». Очистка поискового поля также снимает текстовое ограничение. Полный поисковый текст формируется генератором из записи кейса и включается в HTML; отдельные сетевые запросы и серверная часть не требуются.

В «Давности» два пункта: «Сначала новые» и «Сначала старые». По умолчанию выбрано «Сначала новые». Порядок определяется полем `addedAt` — датой первого добавления кейса на сайт, а не датой первоисточника. Генератор сразу записывает HTML в порядке от новых к старым; переключение списка меняет порядок без перезагрузки и сохраняет выбранные категории. Сброс возвращает все категории и порядок «Сначала новые».

`addedAt` задаётся в формате ISO 8601: например, `2026-11-18` или точная дата и время с часовым поясом `2026-11-18T15:30:00+03:00`. Для будущих кейсов предпочтительна точная дата и время, чтобы различать добавления за один день. При редактировании текста или повторной сборке исходная дата добавления сохраняется. При совпадении дат сохраняется порядок записей в файле. Для уже добавленного Cal AI известна дата 18 ноября 2026 года.

Проверенный справочник сохранён в `content/taxonomy.json`. Смысловые дубли объединены, альтернативные названия хранятся в `content/taxonomy-aliases.json` и не отображаются как отдельные пункты меню. Например, «Для индивидуальных пользователей» преобразуется в «B2C — частным клиентам». Генератор показывает только значения, присвоенные хотя бы одному опубликованному кейсу; все подписи начинаются с заглавной буквы. Новая метка появляется в соответствующем меню после добавления её в кейс и повторной сборки. «Другое» также появляется только при фактическом использовании.

Если для нового кейса нужна категория вне справочника, сначала проверить, нет ли уже того же значения под другим названием. Для синонима добавить соответствие в `content/taxonomy-aliases.json`. Для нового самостоятельного понятия добавить пункт в `options` соответствующей группы `content/taxonomy.json`, затем присвоить кейсу. При сборке учитываются регистр, пробелы и варианты тире; синонимы заменяются единым названием, повторы удаляются. Проверка не позволяет вернуть альтернативное название в справочник как отдельный пункт.

Проверены все пять групп: в программных продуктах объединены «Дополнение / Плагин», «Планировщик / Планировщик задач», «Справочник / Каталог»; в аудитории — повторные формулировки B2C, B2D и B2G; в AI — два названия персонализации; в монетизации — варианты бессрочной лицензии, платной настройки, донатов, патронажа и аренды вещей. В отраслях точных смысловых дублей не выявлено. Самостоятельные понятия, включая компьютерное зрение, мультимодальный AI и RAG, сохраняются раздельно.

В `filters` для каждого кейса нужны массивы `product`, `market`, `industry`, `ai`, `monetization`. Один кейс может иметь несколько меток в каждой группе. Если сведений нет, используется пустой массив: это не то же самое, что «Другое». Для Cal AI монетизация пока не размечена, поскольку предоставленный текст и выбранная статья не описывают конкретную схему оплаты. Метки отражают описываемый период кейса, а не обязательно текущую версию продукта.

Для полного готового описания используется поле `text`, которое выводится целиком без дополнительных разделов. Альтернативный формат `sections` поддерживает массив разделов с `heading` и `text`. Вводный абзац `lead` и примечание `note` необязательны.

Выбранные фильтры применяются совместно: кейс должен соответствовать каждому выбранному условию. Есть сброс, счётчик результатов и состояние без совпадений. Нижний список первоисточников всегда сохраняет ссылки на все опубликованные кейсы.

Рекомендуемая структура материала: кто владеет бизнесом; задача; процесс до автоматизации; что изменилось; роль ИИ и обычной автоматизации; что делает человек; подтверждённый результат; источники.

Все пути относительные, поэтому сайт работает в подпапке `/solopreneurs-radar/`. Тема сохраняется только в браузере посетителя. Внешних шрифтов, аналитики и серверной части нет.
